🔄 ¿Qué son las "Migrations"?

Hasta ahora solo tienes clases C# (código). Si intentas ejecutar la app ahora, dará error porque la tabla "Categorias" aún no existe en SQL Server.

Las Migrations (Migraciones) son el mecanismo que usa EF Core para sincronizar tu código con la base de datos. Es como un sistema de versiones para tu esquema de base de datos.

📜 La Analogía del Plano Arquitectónico

💡 Tu clase Categoria.cs es el plano de una casa. La Migración es la lista de instrucciones que le das al albañil para construir esa casa. Y el comando Update-Database es la orden de "¡Empiecen a construir!".
2

🛠️ Opción A: Crear la BD desde Cero (Code-First)

Si no tienes tablas creadas en SQL Server, EF Core las creará por ti. Sigue estos pasos:

1

Abrir la Consola del Administrador de Paquetes

En Visual Studio, ve al menú superior: Herramientas (Tools) → Administrador de paquetes NuGet → Consola del Administrador de paquetes.

2

Crear el archivo de Migración

Escribe el siguiente comando y presiona Enter. El texto "CrearTablaCategorias" es solo un nombre para que recuerdes qué hiciste.

Add-Migration "CrearTablaCategorias"

Verás una nueva carpeta llamada Migrations en tu proyecto con un archivo que contiene instrucciones Up (crear) y Down (borrar).

3

Aplicar los cambios a la Base de Datos

Ejecuta este comando para que EF Core ejecute las instrucciones SQL en tu servidor:

Update-Database

Si todo sale bien, verás: Done. en la consola.

✅
Verificación

Abre SQL Server Management Studio (SSMS). Conéctate y verás una nueva base de datos llamada NaturVidaDB con la tabla Categorias creada automáticamente (con columnas Id, Nombre, Activo y una tabla extra __EFMigrationsHistory que lleva el control).

3

🗄️ Opción B: Conectar a una Base de Datos Existente

Si ya tienes la tabla "Categorias" creada manualmente en SQL Server (por ejemplo, con scripts CREATE TABLE), no necesitas migraciones. Necesitas que EF Core lea tu tabla y genere las clases por ti. Esto se llama Scaffolding.

Paso 1: Borra las clases manuales que creamos en la Parte 1 (o renómbralas) para evitar conflictos.

Paso 2: En la Consola del Administrador de Paquetes, ejecuta el siguiente comando mágico:

Comando ScaffoldingPowerShell
# Reemplaza "TuCadenaDeConexion" con la real de tu servidor
# Este comando lee la BD y crea las clases C#
Scaffold-DbContext "Server=(localdb)\mssqllocaldb;Database=NaturVidaDB;Trusted_Connection=true;" Microsoft.EntityFrameworkCore.SqlServer -OutputDir Models -Context NaturVidaContext -ContextDir Data -Force
🧩
¿Qué hace este comando?

Se conecta a tu BD, mira las tablas y crea automáticamente:

  • 📄 NaturVidaContext.cs (en carpeta Data/)
  • 📄 Categoria.cs (en carpeta Models/)

¡Es magia! Ya no tienes que escribir las clases a mano. Si cambias algo en la BD (ej: agregas una columna), vuelves a ejecutar este comando y actualiza tus clases.

4

📂 Organización Final

Independientemente de si usaste la Opción A o B, tu proyecto debe verse así al final de esta parte:

NaturVida.App/
│
├── 📁 Models/
│   └── Categoria.cs          ← Generada automáticamente o manual
│
├── 📁 Data/
│   └── NaturVidaContext.cs   ← Tu conexión configurada
│
└── 📁 Migrations/            ← (Solo si usaste Opción A)
    └── 2024...CrearTablaCategorias.cs
